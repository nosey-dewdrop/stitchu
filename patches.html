Patch notes

Every change to the engine, measured and published, the misses included. This is the real development log: what changed, what the accuracy number did, and where a change hoped to bring +6 but only bought +5.

Metric: how many of 54 real product photos become a complete, sewable pattern. Last updated 2026-07-16.

2.12Every pattern page now has a print pack to download2026-07-16
  • Each of the 12 pattern pages now carries a download block. The A4 print pack is the main button: the tiled sheets you tape together at home, with the piece list, fabric estimate and a calibration square on the cover. Beside it sit two dashed links, the A0 single sheet for a print shop and the text-first sewing guide. Every file is the engine's own output at an EU38 body, drawn to true scale.
  • The page count and file size shown on each link are read straight from the pack manifest, not typed by hand, so a page can never claim a size the file does not have. Every sheet carries a 3 cm calibration square to check the print came out at true scale before cutting.
12 pattern pages, 36 downloadable PDFs live · sizes read from the manifest

No accuracy number moves here; this is the shell, not the engine. A download link cannot make a pattern more correct. The PDFs are the same drafted pieces the pages already showed, now packed for the printer. Both site guards stayed clean: style-lint found zero violations and the header is byte-identical across all 44 pages.

2.11The style library joins the baby-blue world2026-07-16
  • The 24 style-library pages were the last corner of the site still wearing the old cherry colour and an off-brand button. They are now regenerated into the same baby-blue world as every other page: navy ink on white, baby-blue accents, and the technical flat sketches redrawn in navy line with a baby-blue accent instead of the old blush. Nothing about the content, the numbers or the layout changed, only the colour and the button.
  • Every call-to-action button on the site now comes from one shared stylesheet, the same filled-navy button with an inner dashed frame you see on the drafter. Every page was swept for a button that did not wear it; the style library was the only offender left, and now the count is zero.
24 style pages now baby-blue canon · off-canon CTAs across the site: 0

No accuracy number moves here; this is the shell, not the engine. A recolour and a shared button cannot make a pattern more correct. But one product should look like one product, and these pages had been left behind on purpose until the rest of the world was settled; now they match. The header stays byte-identical across all 44 pages, verified by diff.

2.10Pages that stay still, and arrive before you click2026-07-16
  • The header still jumped a little when you moved between pages. The cause was the scrollbar: a short page (closet, create) has none, a long one does, and when the bar appeared it stole a sliver of width and shoved everything, header included, sideways. Now every page reserves that sliver whether or not it needs a scrollbar, so the layout width never changes and the header stays put. On top of that, the header and footer are now named for the page-transition system, so when you navigate they hold their place and only the content between them changes.
  • Clicking used to feel like a fresh load. Now, the instant you hover or touch a link, the destination page is quietly fetched in the background, so by the time the click lands it is usually already there and the change feels instant instead of a reload.
header shift on navigation: none · click: prefetched on hover/touch

No accuracy number moves here; this is the shell, not the engine. Both fixes are feel, not fit: a reserved gutter and a named header cannot make a pattern more correct, and prefetch only spends a little bandwidth to hide the load. The header markup is still byte-identical to the previous patch; only two shared stylesheets and one shared script changed.

2.9One header, byte-identical, on every page2026-07-16
  • The navigation bar was still shifting between pages, a little different on each. Now the exact same header markup is on all seven pages plus every style page, and its height, padding and font come from one shared stylesheet, so it can no longer drift by a single pixel from page to page. The nav set is the same everywhere: create, closet, patterns, benchmark, patch notes, API, with the EN·TR toggle. Verified by extracting each page's header and diffing them; all identical except the underline on the current page.
  • The same pass tidied the punctuation on every heading, not just the benchmark's: a statement heading takes a full stop, a question takes a question mark, and a plain label stays bare. One EN/TR toggle now drives the whole site from a single script.
7 pages + 24 style pages, one header · header diff: identical

No accuracy number moves here; this is the shell, not the engine. But a product that shifts under you as you click between pages does not feel like one product, and this had drifted back once before, so this time the sameness is enforced by one file and proven by a diff, not by hand.

2.8The pattern library goes live2026-07-17
  • Every product photo that now becomes a full pattern gets its own page. The library publishes each drafted style, twelve distinct garments so far, with the engine's own pieces laid out for cutting, a piece list, a fabric estimate, and the honest note on which patch made it drawable.
  • The drawings are the engine's own output, drafted live from the same specs the benchmark scored. No source photo is shown or named, only a generic style name, so nothing copyrighted is republished. Each page carries its own search metadata and structured data, so the library is the site's first real content engine.
24 / 54 photos reach full pattern, now published as 12 pattern pages

This patch moves no accuracy number, it publishes the ones already earned. A benchmark that climbs in private is a claim; a library anyone can open and read the pieces of is proof.

2.7Data pipeline scaled to the thousands2026-07-16
  • The photo pool went from hundreds to over 27,000 women's garment photos, dresses, blouses, skirts, sweaters, cardigans, rompers, jackets and more, drawn mostly from a public research dataset plus one more respectful brand pull. Every image is resized, content-hash deduplicated (zero duplicates), and organized by garment type.
  • Same private rule as before: every photo stays local, none is published or shipped. This pool exists only to mine the construction vocabulary the engine still lacks and, later, to train an on-device vision model. Sources and licenses are recorded internally; nothing about them leaves the machine.
FULL 24/54, unchanged · 28,246 photos banked, no engine or vision change

No accuracy number moves here, and it should not. Photos are raw material, not a fix. But you cannot correct a vocabulary you have not seen at scale, and you cannot train your own model on hundreds of images, so the supply line had to reach the thousands before the next real step could happen.

2.6One universe: shared shell across every page2026-07-16
  • The seven pages had drifted into seven looks: different navs, different footers, a stray lowercase api link, and three different favicons and title patterns. Every page now carries the same header (create, closet, benchmark, patch notes, API), the same footer, the same navy dashed favicon, and the same title pattern (stitchu, page).
  • The EN/TR toggle now appears on every page and shares one storage key. The benchmark page had its own key, so switching language there did not carry to the rest of the site; it now writes the same key as everyone else, so your choice follows you across the whole product.
FULL 24/54, unchanged · shell only, no engine or vision change

No accuracy number moves here, and it should not: this is the frame around the work, not the work. But a tool that feels like seven different sites is a tool people do not trust, so the shell had to become one.

2.5Data pipeline online2026-07-16
  • Built a respectful photo collector: it reads public product-listing pages, checks robots.txt, waits 1.5–3 s between every request, and skips any source that objects. First batch: 392 real garment photos (dresses, tops, skirts) from public high-street sources, deduplicated by content hash.
  • Every photo stays local and private, none is published, shown, or shipped anywhere. They exist for two internal jobs only: mining the construction vocabulary the engine still lacks, and later training an on-device vision model.
FULL 24/54, unchanged · infrastructure, 392 photos banked, no engine or vision change

This patch moves no accuracy number, by design. It is the supply line for the next phase: the pattern number is now held back by vocabulary the engine has never seen, and you cannot fix a vocabulary you have not measured in the wild.

2.4API draft endpoint fixed2026-07-16
  • The public /api/draft and /api/grade endpoints were returning 500 engine_error live: the WASM engine crashed inside the Cloudflare Workers runtime. The browser flow was never affected.
  • Root cause was two stacked runtime bans, no C++ or golden change: the worker build read self.location.href (undefined in Workers), and embind built call invokers with new Function (code generation is forbidden). Rebuilt the worker WASM with the web-only environment and no dynamic execution.
/api/draft 500 to 200 · 10 pieces · /api/grade 200 · packaging-only fix, engine unchanged

A packaging bug, not an engine bug: the same C++ engine that draws every browser pattern was fine, only its Cloudflare build was miscompiled for that runtime. The B2B API is now live and verified end to end.

2.3Front/back consistency (reverted)2026-07-16
  • Tried a broader rule: on a back, worn, or close-up detail photo, leave the front-only fields (neckline, shaping, waistline, skirt cut) null instead of guessing them from partial evidence.
  • Measured live, same 59 photos, same conditions. Vision accuracy nudged up (86.8% to 87.0%) but the whole-pattern count fell: a back-view photo the manifest still credited for its neckline went null and dropped out of FULL.
  • Regression guard fired. FULL dropped, so the change was reverted and the 2.2 worker redeployed. This entry stays published, misses included.
FULL 24/54, unchanged · reverted · a broad null rule cost more FULL than it saved

The right instinct, the wrong lever. Blanking front-only fields on partial views is honest, but the benchmark still rewards the back photo for the front's neckline, so nulling it loses a point. The real fix is measurement-side: group the same product's front+back photos and take a majority vote, that is the next loop, not another prompt sentence.

2.2Neckline disambiguation2026-07-16
  • Taught vision that the front and back of a garment are ONE piece with ONE neckline, a back or worn-view photo can no longer invent a different neckline than the front would show.
  • A bow or cut-out at the nape is now read as a back detail, not a halter; halter is reserved for a band that actually wraps the neck. When unsure, vision falls to the common boat/crew/scoop rather than reaching for a dramatic shape.
  • Three back/worn-view photos that used to misread their neckline (a bow-back dress read as halter, two backs read as vNeck/square) now read the correct front neckline.
FULL 22/54 to 24/54 · vision accuracy 86.8% to 94.4% · neckline misreads 5 to 2

A pure prompt change, zero engine code, and it moved the whole-pattern number by two. The two necklines still wrong are genuinely ambiguous FRONT shots, not back-view confusion, an honest ceiling for a wording fix.

2.0Vision error taxonomy2026-07-16
  • Split every miss into its real cause: vision, engine, or the bridge between them. Result: 7 photos lost to vision, 24 to the engine's vocabulary, 0 to the bridge.
  • Added a new metric, vision accuracy, that isolates how reliably the photo is read from how well the engine drafts.
  • The dominant vision error is one field: neckline, on the back/worn-view photo of a garment whose front reads correctly.
FULL 22/54, unchanged · vision accuracy baseline 86.8%

No number moved, and that is the point. A measurement patch does not fix code; it tells the next patch where to aim. The next four fixes are one field wide.

1.9Gathering + open-back cutout2026-07-16
  • The engine now draws the panel gathering itself, drawstring, shirred and smocked zones, instead of pretending the fabric is flat.
  • Added shaped open-back cutouts (round, low-V, square, keyhole) with a facing that finishes the edge, measured to match the drawn opening exactly.
FULL 14/54 to 22/54 · element accuracy 37 to 53 / 103

The queue predicted gathering +6 and open-back +4. Reality: +5 and +3, two photos were clustered behind a second missing element, so drawing one feature didn't complete the pattern.

1.8Metric reform: element accuracy2026-07-16
  • One photo often needs 2–4 missing features, so the whole-pattern count barely moved even as the engine grew. Added a second, finer compass: element accuracy, the share of individual garment features the engine can draft.
  • Re-ordered the build queue from feature frequency to marginal gain, which missing feature actually completes the most photos.
element accuracy first reading 37 / 103 (35.9%)

A hard lesson admitted in public: the single whole-pattern metric was the wrong daily compass. Kept it as the top-line target, added a truer day-to-day one.

FULL 6/54, unchanged
