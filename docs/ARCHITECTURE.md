# stitchu architecture

How a garment photo becomes a printable, body-fitted sewing pattern. Companion docs: `engine/FORMULAS.md` (every drafting formula and its gotchas — the engine's spec), `PROJECT.md` (roadmap), `PLAN.md` (track A/B directives).

## The contract (`contract/`, K1 2026-07-19)

One versioned contract binds every layer boundary. `garment-spec.schema.json`: the SEMANTIC garment language (closed enums + bounded scalars) — the only language the vision model or a human speaks; the render layer is NOT in the contract, each renderer compiles its own parameters from the semantics, and the runtime gate (`web/js/spec-validate.js`, additionalProperties:false) strips any render knob smuggled into a vision answer. `tables.json`: every shared value (skirt lengths mm, EU size chart, gather ratios, flat drawing units, cross-layer word maps like sleeveHead→sleeveCap and the backDetail three-way split) — generated by `engine/tools/gen-contract.mjs` into `engine/src/contract.gen.hpp`, `web/js/contract.gen.js`, `backend/contract.gen.js`; consumers never copy numbers. `terms.json`: the term registry (id, canonical, synonyms, drawable|honest status, capability, evidence) — the benchmark counter's base since the DRAWN_SINCE regex list was retired. Guard: `engine/tools/validate-contract.mjs` runs as ctest `contract_check` and fails on any schema/vocab drift, registry defect, generated-file desync, 58-set unmapped phrase, undeclared flat recipe field, gate-fixture failure, or a create.js picker option outside the vocabulary.

## Layers

```
photo ──> Cloudflare Worker (Claude vision) ──> confirmed GarmentSpec
                                                      │
7 measurements (local) ───────────────────────────────┤
                                                      ▼
                        C++ engine (WASM, in-browser)
                        geometry core → blocks → garment drafter → validator
                                                      │
                                                      ▼
                        web app: SVG render → tiled A4 PDF print
```

### 1. Geometry core (`engine/src/geometry.*`)
Point/Path/cubic-Bezier primitives, seam-length measurement, outline offsetting, intersection and self-intersection checks. Everything above is built on these; they were unit-tested first (`tests/test_geometry.cpp`). Conventions (from `FORMULAS.md`): all geometry in millimeters, each piece in its own local space, curves flattened to 24 segments for length measurement (16 for self-intersection). Gotcha: `boundingBox()` counts curve control points, so comparisons must use flattened boxes.

### 2. Blocks (`bodice.cpp`, `skirt.cpp`, `sleeve.cpp`)
Parametric drafting blocks from published sources (FreeSewing Bella/Titan, Muller & Sohn, Aldrich), driven by 7 measurements plus percent ease (never fixed cm). Documented assumptions (underbust = bust − 70 mm, shoulder drop ≈ 13°) are flagged in `FORMULAS.md` and covered by the muslin warning in the sewing guide.

### 3. Garment drafter + manipulation layer (`garment.cpp`, `ruffle.cpp`, `keyhole.cpp`)
Combines blocks into garments (dress = bodice + skirt + CB invisible zipper; tops with hem variants) and applies the couture vocabulary: necklines (crew/scoop/v/square/boat/sweetheart), keyhole cut-out with shaped facing, halter (a frame-shift over the same bodice skeleton — no separate block), tiered ruffles (tier i edge = edge × fullness^(i−1)), pleats, gathers. Every vocabulary feature is an opt-in `GarmentSpec` field defaulting OFF. Read that as the invariant the per-feature `_check` tests and the golden pin ENFORCE — whether the base draft actually moved is what `ctest` and `golden_check` print, not something this line asserts (standing wording replaced 24 Aug 2026, RULES §6).

### 4. Seam allowance / cut line (`geometry.cpp offsetOutline`)
The piece outline IS the sewing line; the cut line is a drawn outward offset. The outward side is found empirically (probe the longest edge's normal with point-in-polygon — traversal direction is not trusted, an area-sign heuristic once shipped an inward offset). Per-edge offset with miter/bevel joins, then an envelope guarantee: relax passes push any point closer than the allowance back out to exactly it (tames concave curves with radius < allowance, e.g. sleeve underarm). Fold edges are not seams: clamped, exempt from the audit. Strip pieces (ruffles, bias binding) stay single-line — their allowance lives in the cut note.

### 5. Validator (`validator.cpp`)
Geometric invariants run on every draft, and at runtime before any PDF: side-seam balance, dart sums, armhole/cap ease, waist joins, self-intersection, print fit, cut-line sanity. A broken pattern cannot reach the printer. Trim pieces (names containing "Ruffle") are excluded from structural sums by design.

### 6. Verification (tests, golden, fuzz, precision)
- `tests/engine_check.cpp`: the matrix — EU 34-52 + edge bodies × the full spec space = 70,200 drafts, all must validate. Per-feature checks (`ruffle_check`, `sweetheart_check`, `keyhole_check`, `halter_check`, `cutline_check`, ...) assert piece geometry, printability (≤3000 mm tile cap) and that the base draft did not move. How many suites are defined, how many ran and which came back red is what `ctest --test-dir engine/build --output-on-failure` prints — the standing "8 ctest suites" count was measured stale on 24 Aug 2026 (the runner was in the hundreds by then) and replaced under RULES §6 rather than deleted. The red test NAMES from that day's runs, and whether the set grew, are read by `diff`-ing the banked logs under `GECE/log/` (`V2.ctest.before.txt` → `V2-D.ctest.after.txt` for the V2 phase), never from a sentence here.
- Golden: `engine/golden-reference.csv` (committed) is the pinned deterministic reference; `golden-diff.py` compares at 0.1 mm tolerance. History: the C++ engine was ported from Swift against a Swift golden dump (2805 drafts, port fidelity), then the golden was re-pinned to the C++ output when precision truing deliberately improved on the Swift geometry. Every re-pin since is DECLARED in `engine/GOLDEN-PIN.md` — an undeclared re-pin is invalid, and the ledger is where each entry's approval status lives (the 2026-08-24 scye-depth entry is still waiting on Damla, K-V1A). `scripts/repin-golden.sh` is the only honest exit; whether the current tree matches the pin is what `ctest golden_check` prints.
- `tools/precision-report.js` ("the tailor's micrometer"): measures every seam pair a sewist pins; >1.0 mm fails. Found and zeroed a 8-10 mm shoulder-pair gap and a ~2 mm empire side-seam gap. Today's worst pair is whatever `node engine/tools/precision-report.js` prints — the standing "worst pair is now 0.00 mm" wording was replaced on 24 Aug 2026 under RULES §6. Run it after any bodice change.
- `tools/web-fuzz.js`: fuzzes the WEB layer's spec mapping (what `create.js` actually sends to `draftJSON`) across body-corner measurements and simulates the print packer's math. The draft count and the failure count are what the tool prints; the standing "19,555 drafts, 0 failures" pair was replaced on 24 Aug 2026 under RULES §6, same reason as the two lines above.
- **The vocabulary gates (added 24 Aug 2026, V2).** Three ctest entries that hold the CLOSED-ENUM language still, wired in `engine/CMakeLists.txt` with their reasoning in the comment above each `add_test`:
  - `vocab_source_check` — regenerates `vision-student/vocab.py` into a `mktemp` directory and diffs; tolerance is zero bytes. A word the engine cannot ship lands in that file's `_UNRESOLVED` block with its reason, and the gate re-derives that block from `engine/vocab.json` + `contract/vocab-resolution-v1.json` independently of the generator, so the generator cannot pass itself by writing both sides of the diff (mutation evidence: `GECE/log/V2-B.mutasyon.txt`, M1a/M1b).
  - `vocab_reference_check` — a ratchet, PHPStan/Android-lint class rather than a betterer snapshot. References to a closed enum value may fall and may not rise. The floor is the committed `engine/tests/vocab-reference-baseline.json`; both sides are counted in a detached `git worktree`, so the unit is the COMMIT and a dirty tree cannot move the number. Re-cutting the floor is a deliberate `--baseline` commit whose reason goes in the commit message — the two re-cuts this phase are reasoned line by line in `GECE/V2-B.md` §2.1 and `GECE/V2-D.md` §2. A missing floor file is a failure, not a pass.
  - `wasm_spec_honesty_check` — drives the shipped bundle and asserts the boundary refuses rather than coerces (§7). `GECE/log/V2-C.bostest.txt` is the same gate pointed at the pre-phase byte, which is the empty-test proof that it was ever red.

The required loop after engine changes: `engine_check` + `cutline_check` + `precision-report.js` + `web-fuzz.js` + golden diff.

### 7. WASM boundary (`engine/wasm/bindings.cpp`)
A thin embind layer exposing `draftJSON(measurements, spec) → JSON pieces`. Built by `engine/build-wasm.sh` into a single-file bundle (`engine/dist/stitchu-engine.js`), copied to `web/vendor/`. `ls -l engine/dist/stitchu-engine.js` is what prints its size; on 24 Aug 2026 that read 1 209 765 bytes (~1.2 MB), so the "~218 KB" figure this line used to carry was stale by roughly 5.5× and was corrected, not deleted (`GECE/V0.md` §1.4). The same file is `require()`-able from Node, which is how the fuzz/precision/proof tools drive the real engine — no parallel JS implementation to drift.

**The boundary refuses; it does not coerce (24 Aug 2026, V2-C).** Until this phase the conversion layer was the quiet failure point, and both defects were measured on the shipped byte before anything was changed (`GECE/V2-C.md`, log `GECE/log/V2-C.bostest.txt`):

- *Int enums.* `intField()` went through `v.as<int>()`, so truncation happened INSIDE the JS→C++ conversion and `parseEnumInt` never saw the real value — a spec asking for `sleeveCap 1.5` drafted as `1`. All 26 int axes now read through one `enumIntField()`: a non-integral, non-finite or out-of-range value is refused BY NAME, in the same `specparse.hpp vocabError` words the string axes already use (`invalid sleeveCap '1.5' (valid: plain, gathered, puffed, …)`). Absence is still not an error — an undefined key keeps the default. `ruffleTiers` is a count rather than an axis and was going through the same truncation; it is bound to the strict reader too.
- *Body fields.* `numField()` turned a key it could not find into `0`, and a missing measurement is not a zero measurement. `bodyFrom()` now names the offending measurement in the recipe interpreter's own words (`recipe.cpp:938`, one fault one language); `upperBust` stays optional (0 = not declared). The zero body was also what produced the `collarType` NaN — the real root was a missing `shoulderLen < 1e-6` latch in `bodice.cpp makeFacing()`, and `num()` printing a bare `nan` token made the validator's honest verdict unreadable as JSON. `num()` now refuses to print a non-finite number and the throw is caught into `{"error": …}`, so the failure is noisy instead of hidden. `gradeJSON`, `draftRecipeJSON` and `dxfRecipeJSON` carry whole-body try/catch for the same reason.

**The shipped artefacts carry a source digest (24 Aug 2026, V2-D).** `build-wasm.sh` prepends a line-1 comment to both glue files and appends a `stitchu.source-stamp` custom section (wasm id 0, spec-legal, ignored by every runtime) to `backend/engine/stitchu-worker.wasm`, all three carrying a sha256 of `engine/src` + `engine/wasm` + `build-wasm.sh`. The reason it is a digest rather than the producing commit sha is written in the script: a sha is only right if the build runs after the source commit, and the normal order (edit → compile → one commit) builds from a dirty tree, so a sha stamp would re-emit the same value and leave `bundle_fresh_check` red — the very defect being repaired. A digest is also deterministic, so a rebuild with no source change produces no diff. Two limits are declared rather than glossed (`GECE/V2-D.md` §6): `engine/dist/` is gitignored and unstamped, and the gate reads the stamp as an assertion instead of recomputing it from content.

### 8. Web app (`web/`)
Static, framework-free, GitHub Pages. `store.js` (measurements + closet, local), `analyze.js`/`create.js` (photo → Worker → confirm → draft), `render.js` (SVG pieces with darts, grainline, double cut/sew line), `print.js` (client-side tiled A4 PDF, 3 cm calibration square, 190×250 mm printable page, page map), `wall.js` (communal stitch wall via Worker KV). EN/TR i18n. Cache-busting is manual: bump `?v=N` on every deploy (deploy = `git subtree split --prefix web` → `gh-pages`).

### 9. Backend (`backend/worker.js`)
One Cloudflare Worker: proxies garment analysis to Claude vision. The browser never holds the API key — it sends a shared app token; the key is a Worker secret. Rate-limited (20/min app-token; public mode 3/min, 15/day per IP), hardened per the 2026-07-13 ship-check. Also serves the stitch wall (KV). Planned: `POST /api/draft` running the same WASM engine server-side — the sellable API.

### 10. Track B — owning the vision (`vision/`)
Goal: kill the per-call LLM cost. The vision step is bounded classification into a fixed vocabulary. Measured on a hand-labeled eval set: zero-shot CLIP 44%, SigLIP 65% (dead end vs a ~95% product bar); Opus via the live worker 86%. v1 plan: Opus as teacher auto-labels a licensed image corpus (pipeline in `vision/corpus`) → train small per-attribute heads → ship as browser ONNX next to the WASM engine, zero marginal vision cost. Numbers and method: `vision/README.md`.

**`vision-student/vocab.py` is a BUILD PRODUCT as of 24 Aug 2026 (V2-B).** The file opened with the sentence "The classes MUST stay identical to the teacher schema" and nothing audited it; measured against `engine/vocab.json` it was false on three of its four lists. It is now emitted by `engine/tools/gen-vision-vocab.mjs` from the two committed tables (`engine/vocab.json` as the authority, `contract/vocab-resolution-v1.json` as its lower layer) and held there by `ctest -R vocab_source_check` — run the generator, don't hand-edit the file. The exported names (`NECKLINE_CLASSES`, `GARMENT_CLASSES`, `SLEEVE_LENGTH_CLASSES`, `SKIRT_STYLE_CLASSES`, `FIELDS`, `UNCERTAIN_VALUES`, `classes_for`, `label_to_index`) were preserved because eight modules under `vision-student/` import them. Nothing was deleted: a word with no engine axis lands in `_UNRESOLVED` with its reason. ⚠ **Open consequence, not decided:** `NECKLINE_CLASSES` went 7 → 9 and `SKIRT_STYLE_CLASSES` 5 → 6. Declaration order was preserved so no existing label index shifted, but a head trained with the old output count no longer matches the class count — whether retraining is required is unresolved (`GECE/V2-B.md` §1).

⚠ **2026-08-17 (T10):** the 780 fetched rasters (166MB, the single largest tracked directory in the repo) were **removed from the tree and gitignored**. Measured first: zero references in `engine/CMakeLists.txt`, `engine/tests/`, `scripts/`, `backend/`, `web/js/`, `contract/` — the only two files naming them are `vision/fetch-corpus.sh` (the producer) and `vision/live-eval.sh`, both inside this same not-started track. `vision/corpus/manifest.json` (every photo's source URL + licence) and the fetcher stay tracked, so `./vision/fetch-corpus.sh` rebuilds the corpus. **Track B is a plan, not a shipped path** — the v0 numbers above are the whole of it.

## Data flow summary

- Measurements: entered once, IndexedDB/local only, never leave the device for drafting.
- Photo: leaves the device only for the vision call (Worker → Anthropic), user confirms the classification before drafting.
- Drafting: 100% client-side (WASM) — zero server cost per draft, and simultaneously the KVKK/privacy answer.
- Pattern: SVG + PDF generated in the browser; saved patterns live in the local closet (full CRUD).
- Knowledge: `knowledge/schema.sql` + seeds → `stitchu.db`; formula claims enter as `verified` only after adversarial source-checking, refuted claims kept so they are never reused.

## Key design decisions

- C++ core, multiple consumers: one engine feeds web (WASM), Node tooling (same bundle), later iOS (static lib) and Android (NDK). Chosen over Rust deliberately (synergy with coursework); the golden matrix is what made a full Swift→C++ rewrite safe.
- Client-side drafting: no server cost, no measurement upload, shareable static hosting.
- Spec-driven port: `FORMULAS.md` is the source of truth, not line-by-line translation — the port implements the spec.
- Opt-in vocabulary: every new feature defaults off, and the draft matrix plus the base-draft golden pin are the gates that decide whether it stayed clean. Their verdict is read from their own output (`ctest`, `golden_check`), never asserted here — the standing-claim wording this line used to carry was replaced on 24 Aug 2026 under RULES §6, after `golden_check` was measured red (`GECE/V0.md` §1.2). That red was later traced to a deliberate behaviour change and answered with a declared re-pin (`engine/GOLDEN-PIN.md`, 2026-08-24, Damla approval still open) — which is why the gate's verdict is read from the runner and the ledger, and is not restated as a fact here.
- Prove, don't claim: a feature exists only when it is in `engine/src`, has a passing `_check` test, renders correctly, and survives the matrix + golden + precision + fuzz loop (discipline codified in `PLAN.md`).
- One truth, one place: neck width, armhole curve, binding length each have a single computing site; derived values are measured from the same geometry, never recomputed.

## Known limits

- Trousers not drafted (needs crotch depth + cross seam, not collected); no wrap/collar/pocket/off-shoulder/cowl yet (`engine/SPECS-next-vocabulary.md` is an UNVERIFIED agent draft — review before building).
- Bodice carries documented assumptions (underbust offset, shoulder slope); geometric validation is complete but a physical sew test against a commercial pattern is still pending (roadmap item 24 — miniature garments first).
- Vision is rented (Opus per call) until the Track B student ships; its accuracy ceiling is the 86% teacher.
- Keyhole ships as stitch-line + facing with an honest skip note; halter's cramped-back case falls back to dart mode by rule.
- Deploy/cache is manual and fragile: forgetting the `?v=N` bump serves stale assets (Safari).
