STITCHU — HONEST DEPTH DIAGNOSIS
2026-07-17

The question this answers: of the patterns the engine DRAWS, how many are
actually CORRECT — meaning they fit a real body and sew up right — not just
"a full set of pieces was emitted"? This is written after reading the
benchmark tooling, the results, and every proof tool (fit_proof, precision-
report, virtual-sew, wearability, golden). It is deliberately unflattering
where the evidence is thin.


1. WHAT IS ACTUALLY PROVEN TODAY (with numbers)

- The engine emits a full, self-consistent pattern for 37 of 54 real garment
  photos ("37/54 FULL", the live figure; the committed results file in this
  worktree still reads 24/54 because the Jackie-combo reclassify persisted in
  another worktree that had the private manifest — the 37 is the number the
  live site publishes). Element accuracy: ~71/103 out-of-vocab construction
  elements are now drawable (~68.9%).

- CRITICAL: "FULL" in benchmark-58.mjs means exactly two things and NOTHING
  MORE. Read classify() (lines 186-210): a photo is FULL when (a) the VISION
  spec's fields match the manifest's accepted values, and (b) every out-of-
  vocab construction element the photo needs is in the engine's DRAWN_SINCE
  list. That is: "vision read it right AND the engine has a code path that
  emits those pieces." It does NOT open the pieces, measure them, or compare
  them to any body or reference draft. FULL proves EMITTED, not FITS.

- Internal consistency IS strongly proven, and this is real engineering value:
  * golden diff: byte-identical against golden-reference.csv (the engine's own
    frozen past output) — proves no unintended change, i.e. reproducibility.
  * precision-report.js: every seam PAIR that gets pinned together (shoulder,
    side, princess, waist join, sleeve cap, facing) mates within <1.0mm across
    3 bodies x 3 specs. Worst pair 0.00mm. Proves pieces that sew together have
    equal-length edges.
  * virtual-sew.js: seams meet at the right POINTS, not just the right lengths.
  * wearability (wearability.cpp, a validator gate): blocks drafts that are
    physically un-donnable — head can't enter, a "cut on fold" piece that also
    claims a front placket, raw edges with no finish. This killed a real bug an
    external LLM found by hand. Good, permanent guard rail.
  * vocab-sweep 37800 drafts / 0 validator issues, web-fuzz 20k+/0.

  All of the above prove the pattern is CONSISTENT WITH ITSELF and ASSEMBLABLE.
  None of them compares the result to a real body.


2. WHAT IS NOT PROVEN (the depth gap)

- FIT. No test compares a drafted garment against a real EU38 (or any) body or
  a known-good reference draft/sloper. Look at fit_proof.cpp — it is the only
  test that even claims "fit", and it is close to tautological:
    * It measures the finished WAIST off the sewn pieces and asserts it equals
      waist * (1 + ease). But the engine DREW the waist as waist/4*(1+ease), so
      the test confirms the geometry realized its own scalar. It proves intent
      landed, not that the ease/block SYSTEM fits a human.
    * It explicitly SKIPS the bust (comment lines 64-70: the naive max-span read
      catches the shoulder, so bust is "correct by construction" and not
      asserted). The single most fit-critical girth is not checked at all.
    * Sleeve, armhole depth, neckline gape, dart placement, rise/length balance
      — none validated against a body, only against internal targets.

- The engine rests on UNVALIDATED assumptions (FORMULAS.md assumption ledger,
  honestly labelled 2026-07-17): shoulderDrop = shoulderHalf*0.23, biceps ratio
  0.30, button 18mm are UNVALIDATED design assumptions — "validate with a
  muslin/toile". No muslin has been sewn.

- Roadmap item 24 (physical sew test / miniature-then-muslin validation) is
  still UNCHECKED "[ ]". The "sew it and measure" test has NEVER been done.
  Every fit claim on the site is therefore internal-consistency dressed up. The
  site's honesty layer already admits this ("internal consistency, not a fit
  proof", muslin caveat visible) — which is correct and should stay.

- So the honest answer to "of the patterns the engine draws, how many are
  actually correct (fit + sewable)?": SEWABLE — strong evidence for all 37
  (seams mate, assembles, donnable). FITS A REAL BODY — proven for ZERO. Not
  one drafted garment has been checked against a body or a reference draft, let
  alone sewn.


3. THE SINGLE HARDEST UNSOLVED PROBLEM (ranked)

  (a) NO FIT VALIDATION. The drafted measurements have never been shown to
      produce a garment that fits. This is the whole product promise and it is
      unproven. HARDEST + most important. Everything else is downstream of this.
  (b) Grading correctness (EU34-52). Grading = re-drafting the spec per standard
      body; grade_check only asserts monotonic growth + validator-clean, never
      fit-per-size. Same gap as (a), multiplied across sizes. Blocked by (a).
  (c) Flat/fit at real body proportions (necklines gaping, dart sufficiency on
      full busts, armhole depth). A subset of (a) — needs the same body-truth.
  (d) Vision->spec accuracy on hard photos. Real but SECONDARY: it is ~94% on
      the set and, per prior audits, most misses are ambiguous back/front photos,
      not a systemic engine problem. It gates the benchmark count but is not the
      depth wall.

  Rank: (a) >> (b) ~ (c) > (d). The one hardest unsolved thing is (a): there is
  no ground truth for FIT anywhere in the system.


4. THE CHEAPEST NEXT EXPERIMENT TO ATTACK IT

  Do the "measure the flattened pattern against a reference draft" test — the
  cheap, fabric-free half of roadmap 24 — BEFORE any sewing:

  1. Pick ONE known body (EU38: 88/70/94...). Draft a plain fitted bodice +
     straight skirt with the engine (already scriptable via engine/dist).
  2. Draft the SAME body's block by an independent published method (Aldrich
     or Armstrong) by hand ON PAPER, or use a commercial EU38 sloper Damla can
     buy/already has (a real sloper is the gold reference).
  3. Flatten the engine pieces (the flatten code already exists in fit_proof/
     precision-report) and MEASURE key landmarks against the reference: neck
     width + depth, shoulder length + slope, armhole depth, bust width at chest
     line, waist dart intake, front/back balance, waist and hip girth.
  4. Report each landmark's error in mm vs the reference. That single table is
     the first real external fit signal the project has ever had, and it costs
     0 fabric and 0 LLM credits — just one careful draft comparison.
  5. THEN, only for landmarks that pass on paper, sew ONE muslin bodice (the
     expensive confirmation) — but the paper comparison will already have caught
     the gross errors cheaply.

  Expand to ~10 patterns (the strategy doc's "10 people sew it" in its cheap
  form: 10 drafts vs 10 reference landmarks) once the harness on pattern #1
  works. Turn each confirmed error bound into a permanent fit_check assertion,
  the same way the wearability bug became a permanent gate.

  This converts "fits — trust me" into "fits within N mm of a published draft,
  measured." That number, not 37/54, is the depth metric the product actually
  needs.


BOTTOM LINE
37/54 measures DRAWS + vision-reads. Sewability is well proven. Fit is proven
for nothing. The depth move is not more garments — it is one honest paper
comparison of a drafted pattern against a real sloper, and the mm error it
reports.
