One endpoint. Real patterns. No AI bill.

The same C++ drafting engine stitchu runs in the browser, behind one HTTP endpoint. Send seven measurements and a garment spec; get back a true-scale, measurement-fitted sewing pattern, pieces, a construction guide, and a fabric estimate. The engine does the drafting, so there is no per-call AI cost.

POST /api/draft · zero marginal cost

Request

curl https://stitchu-api.<account>.workers.dev/api/draft \
  -H 'content-type: application/json' \
  -d '{
    "spec": { "garment": "dress", "neckline": "sweetheart", "ruffle": "tiered" },
    "measurements": { "bust": 92, "waist": 74, "hip": 98,
                      "shoulder": 39, "backLength": 42, "armLength": 58, "neck": 36 }
  }'

Response

{
  "apiVersion": "1",
  "pattern": {
    "garment": "sweetheart dress",
    "fabricMeters140": 7.0,
    "guideSteps": [ "Print and check the 3 cm calibration square…", … ],
    "pieces": [
      { "name": "Bodice Center Front", "cutInstruction": "cut 1 on fold",
        "commands": [ {"type":"move","x":0,"y":8}, {"type":"curve","x":61,"y":0,"cp1x":34,…} ],
        "seamAllowance": 15 }
    ]
  }
}

Coordinates are in millimetres; every point is a flat key on the command. An impossible body or an unsewable combination returns 422 undraftable with the reasons, the API never returns a pattern that would waste a customer's fabric.
