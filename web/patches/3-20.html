3.20

One contract, one term registry: the counter's regex rules are retired and every shared number now has a single home.

2026-07-19
  • The same word used to carry three different numbers in three engines (a mini skirt was 87 units in one drawing tool, 42 in another, 450 mm in the pattern engine). Every shared value (hem lengths, the EU size chart, gather ratios, the vision-to-engine word translations) now lives in one versioned contract (contract/), and the C++ engine, the web, the worker and the flat renderer all read generated copies of it. The relocated values are provably unchanged: the engine binary came out byte-identical.
  • The benchmark counter used to decide what counts as drawable with 16 regular expressions. Those are deleted. Capability is now a declaration in a public term registry (contract/terms.json): every construction word has an id, synonyms, a drawable-or-honest status and the evidence its drafted pieces must show. An unmapped phrase can never count drawable by accident, and the leak scan reports zero unmapped phrases across the 58-photo set. The registry also declared two capabilities the regex list had silently forgotten: the engine has drafted patch and side-seam pockets since patch 3.12, so element accuracy rises honestly from 71/103 to 74/103 (71.8%), and the full-pattern count moves by exactly zero from it, because every pocket photo is still blocked by another element.
  • The proof-checked number moves 23 to 27 of 54, and none of that movement comes from the new counting base. Two repairs caused it, both published: the repo's node engine copy was stale (it predated the named-spec boundary, so every draft-proof threw and fell to PARTIAL; it was rebuilt and is now byte-identical to the live web build), and 12 of 54 cached vision readings were missing from the measurement snapshot and were re-run live (12 vision calls spent; this loop was meant to be zero-call, the miss is declared, not hidden). On the repaired cache the retired regex rules and the new registry give identical verdicts, pockets aside.
  • A second, harder number is published next to the 58-set: frequency-weighted corpus coverage. Across 5,092 out-of-vocab observations on 1,600 wild retail photos, the engine's drawable share is 6.7%. The curated set says what the engine does on chosen photos; this says what it does in the wild, and it is deliberately brutal.
  • The vision layer is now schema-gated: a vision answer is validated against the semantic contract before anything consumes it. Unknown fields (a renderer knob smuggled into an answer) are stripped, out-of-vocabulary values are nulled, and a permanent test suite guard (contract_check) validates the schema, the registry, the generated copies and the gate on every run.
counter base + contract · full patterns 23→27 of 54 proof-checked (cache repair, not counting change) · element accuracy 71→74 of 103 · corpus coverage 6.7% published · engine byte-identical

Two housekeeping truths, published because hiding them would poison the numbers: this loop spent 12 vision calls repairing a cache that should never have been broken, and the previously reported 23 was measured on a snapshot that can no longer be rebuilt. From this patch on, the counting base is a data file anyone can read, diff and dispute; that is the point of a contract.
